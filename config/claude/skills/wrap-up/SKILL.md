タスクの締め。順に行う。補足: $ARGUMENTS

## 1. 前提の確認
- `git status --porcelain` でコード変更が残っていないこと（残っていれば先にコミットを終える。hook が拒否する場合は証拠が足りないので戻る）
- S 規模だった場合: 起点の issue があればコメント 1 つで終わり。記憶は残さない

## 2. 情報の振り分け（置き場所はここで判断する）
このセッションで分かったこと・決めたことを 1 件ずつ、次の表で置き場所を決める。同じ内容を複数の場所に書かない（詳細は 1 か所、他は参照）。**迷ったら残さない**。コード・README・git log から導けることは残さない。

| 置き場所 | 入れるもの | 読む人・タイミング |
|---|---|---|
| **Linear**（起点の issue のコメント。無ければ作る） | 作業の結果と状態: やったこと、検証（コマンドと結果）、レビュー結果、決定と理由、残件・判断待ち、見送ったこと | 人が後から経緯を追う。状態（In Progress / Done）は「Done にしてよいか」を確認してから変える |
| **プロジェクトの `CLAUDE.md`**（リポジトリ、Edit で追記して別コミット） | 毎セッション最初から必要なこと: ビルド・テスト・実行のコマンド、守るべき不変条件、規約、「これはやらない」。短く安定したものだけ | そのリポジトリで動く全エージェントが毎回 |
| **グローバルの `~/.claude/CLAUDE.md`**（dotfiles） | 全プロジェクトに効く規則・好み。**追記はユーザーに提案し、合意してから** | 全プロジェクトで毎回 |
| **tinymemory `fact`** | 毎回は要らないが関連時に効く知識: 決定と理由、ハマりどころ、環境の癖。全プロジェクト共通の好みで規則ではないものは `--global` | 関連するときに recall / search で |
| **tinymemory `session`** | やったこと・現在の状態・次の手順（M / L では必ず 1 件。150 行以内） | 次のセッションの開始時に自動で |
| **残さない** | デバッグの途中経過、試行錯誤の履歴、一時的な状態、他の場所にあるもの | — |

昇格・降格・更新:
- 既存の fact を `tinymemory search` で確認し、**同じ話題があれば同じタイトルで保存し直す**（supersede）。間違いになったものは `tinymemory delete <id>`
- fact が 2 セッション以上続けて必要だったなら、プロジェクトの CLAUDE.md に移して fact は削除する
- CLAUDE.md の記述が状況依存になっていたら、fact に降格する

## 3. 保存
- Linear: 上の見出しでコメントする
- CLAUDE.md: Edit で追記する（プロジェクトのものは別コミット。グローバルは提案まで）
- tinymemory: remember の手順どおり `tinymemory save --type session --title "…"` と `--type fact` を quoted heredoc で実行する

## 4. 報告
残したものを「置き場所: タイトル」で 1 行ずつ列挙し、残さなかった判断も 1 行で述べ、最後に `/clear` してよいことを伝える。
