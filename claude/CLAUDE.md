# Global instructions

## 実装タスクの進め方

実装を伴うタスクでは Agent Teams パターンを使う。1人で全部やらず、フェーズごとに別エージェントに委譲する:

1. **設計** — `subagent_type: Plan` で実装計画・トレードオフを出させる
2. **実装** — `subagent_type: general-purpose` （または該当する特化エージェント）にコーディングを任せる
3. **レビュー & 動作確認** — 別エージェントで差分レビューと動作テストを行う

各エージェントは独立した文脈で動くため、設計者の意図に引きずられない独立したレビューが得られる。委譲する際は、前のフェーズの成果物（プラン、変更ファイルパス、確認すべき挙動）を明示的にプロンプトに含めること。

該当しないケース: 単純な質問への回答、1ファイル数行の編集、調査のみのタスク。

## Git commit messages

- 1行で簡潔に書く（タイトルのみ、本文は付けない）
- `Co-Authored-By: Claude ...` などのモデル署名は **付けない**
- HEREDOC ではなく `git commit -m "..."` の単純形でよい

## Python

- Python の実行は **すべて `uv` 経由**で行う (`uv run script.py` / `uv run python -c '...'` / `uv run pytest` など)。素の `python` / `python3` を直接呼ばない。
- ライブラリインストールは **`uv add <pkg>` を最優先**。`pyproject.toml` を管理しないスクリプトや、`uv add` がエラーになるケース（PEP 517 非対応、ローカルパス指定など）に限り **`uv pip install` にフォールバック**。
- 新規プロジェクトでは最初に `uv init` を実行する。
